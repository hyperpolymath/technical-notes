= Usage — technical-notes
:revdate: 2026-07-27

== Audience

This document is for *readers and citers* of `technical-notes` — people
who want to read a note or cite it in their own work. For people
drafting or revising a note, see link:./contributing.adoc[contributing.adoc].

== Reading a note

Each note lives at the repo root as a Markdown file (`<slug>.md`), listed
in the README table. Some notes also ship a Typst source (`<slug>.typ`)
and a rendered PDF (`<slug>.pdf`) as a typeset reading copy.

== Citing a note

Use the **concept DOI** from the README table — it always resolves to
the latest version, so citations do not go stale as a note is revised:

[source]
----
Jewell, J. D. A. (<year>). <Note title>. Zenodo. https://doi.org/<concept-DOI>
----

To cite a specific revision instead of "latest", use that version's DOI
(also listed in the README table).

== Licensing

Each note's licence is set at Zenodo-deposit time and recorded in that
note's own Zenodo metadata; it is not necessarily the same licence as
this repository's own tooling and process documentation. See the root
`README.md` § Licence and the per-file SPDX headers in this repo for
those.

== Stability guarantees

* A note's **content**, once deposited, is versioned — a revision gets a
  new version DOI under the same concept DOI; nothing is silently edited
  in place on Zenodo.
* The **README table** is the index of record for which notes exist and
  their current DOIs.

== Limits & known constraints

* The Zenodo–GitHub integration is not yet enabled (see README § Zenodo
  archiving); until it is, new versions are deposited directly via the
  Zenodo API rather than via a GitHub Release.
